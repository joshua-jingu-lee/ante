# RFC 7807 에러 응답

> 소스: [`src/ante/web/errors.py`](../../../src/ante/web/errors.py)

RFC 7807 (Problem Details for HTTP APIs) 표준을 따르는 에러 응답 포맷.
`register_exception_handlers(app)`으로 FastAPI 앱에 등록한다.

응답 필드는 표준 RFC 7807 스키마를 따르며, Pydantic 스키마는 [08-pydantic-schemas.md](08-pydantic-schemas.md)의 `ErrorResponse` 참조.

모든 라우트의 *명시 등록된* 4xx/5xx `responses` 항목은 `model: ErrorResponse`를 사용한다(invariant).

명시 등록된 4xx/5xx `responses` entry는 OpenAPI 노출 시 `application/problem+json` content-type만 사용하며, 런타임 응답 content-type(`PROBLEM_JSON`)과 일치한다(invariant, #1164).

**Validation error sanitization (invariant, 보안 — L1: 값 반사 금지, #1629 / L2: `extra_forbidden` loc 말단 정규화, #1650 / L2 비-`extra_forbidden` 하이브리드 정책: discovery lock, #1651)**: 422 validation 응답 detail은 거부된 입력 **값**을 반사하지 않으며, Pydantic `error["type"] == "extra_forbidden"` 항목의 `loc` **말단 세그먼트**(거부된 caller extra 필드의 **키 이름**)는 고정 placeholder 토큰 `[extra]`로 정규화된다. 비-`extra_forbidden` caller-supplied 문자열 식별자 `loc` 벡터는 런타임 일반정규화 대신 **정적 default-deny discovery lock**으로 merge 전 봉인된다(#1651, 옵션3 하이브리드).

- **L1 (값/`input`/`ctx`/`msg` 반사 금지, #1629)**: (1) raw-body 핸들러는 공용 chokepoint `sanitize_validation_errors(e)`(= `e.errors(include_context=False, include_input=False)` + `_normalize_error_loc`, pydantic `ValidationError`), 글로벌 `RequestValidationError` 핸들러는 `_sanitize_pydantic_errors(exc.errors())`(= `input`/`ctx` 제거 + `_normalize_error_loc`)를 사용한다. (2) web request 모델 validator 메시지는 거부된 raw value를 `msg`에 interpolation하지 않는다(필드/제약만 명시). `type`/`msg`/`url`만 노출. 신규 raw-body validation 핸들러·validator는 본 invariant를 의무 준수하며, raw-body 사이트는 `e.errors(include_input=False)` 직접호출 대신 공용 chokepoint `sanitize_validation_errors`만 호출한다(직접 호출 잔존 0 — SSOT).
- **L2 (`extra_forbidden` loc 말단 정규화, #1650)**: 두 sanitization 경로(글로벌 `_sanitize_pydantic_errors` / raw-body chokepoint `sanitize_validation_errors`)는 `_normalize_error_loc`로 **`type=='extra_forbidden'` 항목 한정** `loc[-1]`(거부된 caller extra 필드 키)을 고정 placeholder `[extra]`로 치환한다. static `loc` prefix(`body` 등)·`type`/`msg`/`url`·HTTP 422·RFC7807 envelope는 보존한다(현 `extra="forbid"` 요청모델은 전부 flat `BaseModel`이라 extra 키는 항상 `loc` 말단 — #1643 v-series AST 실측). 본 정규화의 **보안 단언은 `type=='extra_forbidden'` loc 벡터에 한정**한다.
- **L2 비-`extra_forbidden` 하이브리드 정책 (옵션3, #1651 — 결정 출처: 2026-05-17 사용자/대표 옵션3 하이브리드 채택, 2026-05-18 사용자/대표 수열 인덱스 정책 = 해석 B)**: `extra_forbidden`을 제외한 caller-controlled `loc` 벡터(자유형 `dict[str,*]` 필드의 **키**, structured body[dataclass/TypedDict/NamedTuple/RootModel], typed `__pydantic_extra__`, validator/`Annotated[*Validator]` 합성 `loc`, root-container body)에 대한 종합 정책은 다음 5절로 확정한다.
  1. 422 validation error의 `loc`는 static schema field-path만 외부 응답에 보존해야 한다. **여기서 invariant 위반인 'caller-controlled segment'는 caller-supplied 문자열 식별자(거부된 extra field key 이름 / 자유형 `dict[*]` 키 / opaque·structured 이름)에 한정한다(2026-05-18 사용자 결정 = 해석 B).** **bounded 정수 수열 인덱스**(`list`/`tuple`/`set` element 위치, 예 `loc=['scopes', 0]`의 `0`)는 list 검증에 구조적·보편적이고 L1(#1629)이 값/`input`을 제거해 caller-named 콘텐츠를 무노출하므로 **본 invariant 대상이 아니다**(static-structural diagnostic으로 허용; **명문 제외**). 즉 invariant 위반 segment ≡ caller-supplied 문자열 식별자이며, 수열 인덱스는 위반에서 명시 제외된다.
  2. `extra_forbidden`의 거부된 extra field key는 L2(#1650)에서 런타임 placeholder 정규화한다(위 항목 참조 — #1650 소유, #1651 비대상).
  3. 비-`extra_forbidden` caller-controlled `loc` 벡터는 현재 일반 런타임 정규화하지 **않는다**(caller-supplied 키/이름 벡터 기준 현재 live 노출 0건이므로 옵션3에서 일반 런타임 `loc` 정규화기를 도입하지 않는다 — 2026-05-17 사용자 결정).
  4. 대신 request validation surface 전수 **default-deny discovery lock**을 회귀 게이트로 둔다. lock은 안전성이 증명된 annotation node만 PASS시키고, 미증명/opaque shape는 **fail-closed**로 막는다(아래 Discovery Lock Contract).
  5. lock이 막는 표면이 실제 제품 기능에 필요해질 때는 그 표면에 한해 별도 spec/issue에서 targeted runtime normalization, schema redesign, 또는 justified-unreachable + guard를 결정한다. 이때 일반 런타임 정규화로 확장하려면 static schema path와 caller-controlled segment를 안정적으로 구분하는 설계를 별도 증명해야 한다(**follow-up rule**: 묵시 확장 금지 — 옵션3 = 지금 미도입이 사용자 확정).
- **#1650 / #1651 범위 분리 (명문)**: #1650(L2)은 유일 live 벡터인 `type=='extra_forbidden'` loc 말단 런타임 정규화만 소유하며 #1651이 #1650 범위를 확장하지 않는다. #1651(L2 하이브리드)은 **런타임 무변경** — 비-`extra_forbidden` 벡터를 정적 discovery lock으로만 봉인하고 `errors.py` 런타임(`_normalize_error_loc`/`_sanitize_pydantic_errors`/`sanitize_validation_errors`)은 #1650 그대로 둔다. discovery lock은 **test-only**이며 OpenAPI 스키마 계약(`loc`은 스키마 계약 아님)에 무영향이다.
- **Discovery Lock Contract (#1651, default-deny)**: lock은 검사 surface를 손-열거하지 않고 introspection으로 **self-enumerate**한다(surface·validator·registry의 개수도, 고정 모델/필드 멤버명도 normative하게 하드코딩하지 않는다 — introspection self-derive가 유일 SSOT, 미등록·미증명 항목은 fail-closed). surface = **S1(raw-body Pydantic 검증 callee 모델 annotation-tree walk + origin-complete fail-closed 가드) ∪ S2(`create_app()` route 재귀 순회 — Mount/sub-app 내부 포함; positive-type 증명된 non-validation mount만 면제)**. annotation-tree default-deny walker는 safe-allowlist(스칼라/`Enum`/`Literal`/`Any` · 인식 container 재귀 · **정확히 `dict[str,Any]`만** · `BaseModel`[`extra∈{forbid,ignore}`·typed `__pydantic_extra__` 부재·validator-clean·fields recurse-safe]) 양성 매칭만 PASS시키고, 그 외 일체(dataclass/TypedDict/NamedTuple/RootModel/`dict[str,T≠Any]`/`dict[K≠str,*]`/`extra='allow'`/validator-bearing 미등록/opaque/unknown shape)는 fail-closed FAIL한다. 비-`dict[str,Any]` dict 노드는 소유 모델 `model_validate` **이전** reject 분기(예 4xx)가 발화하고 `model_validate` 미호출임을 behavioral로 증명한 등록 증명(pre-validation-reject precedence guard)이 있을 때만 PASS한다. validator/`Annotated[*Validator]` surface는 lock이 `__pydantic_decorators__`(field/model validators + v1호환 `.validators`/`.root_validators`) ∪ `Annotated[*Validator]`로 self-enumerate하여 그 집합 ⊆ behavioral canary 등록집합(미등록 1개라도 FAIL)을 단언한다. **S2 introspection·annotation-tree walk·validator census 의미는 CV1/CV3 canary 테스트가 게이트**이며, FastAPI 검증판은 **`fastapi==0.135.1`**이다(upper-bound 없음 — canary가 version-agnostic 1차 게이트).
- **L2 범위 외 (F3 — #1651 lock 비대상, 후속 후보)**: `PUT /api/accounts/{id}` raw-body의 **수동 unknown-key 422**(`accounts.py:644-648` — Pydantic `extra_forbidden` 미경유, unknown key를 직접 detail 문자열에 join = F3 벡터)는 Pydantic `loc` 메커니즘이 아닌 detail-string 직접반사로, #1650 L2 정규화 대상도 #1651 discovery lock 대상도 **아니며** 별도 F3 후속 후보에서 다룬다.
